# 项目阶段计划

原则：每阶段完成后先测试、汇报结果并等待项目所有者确认，再进入下一阶段。未经确认不启用生产采集、不产生付费调用、不绑定正式域名。

## 阶段 1：项目基础与方案定稿（当前阶段）

- [x] 建立独立 GitHub 仓库
- [x] 明确静态网站方向
- [x] 明确初期不使用数据库
- [x] 明确无注册、登录和会员功能
- [x] 固定新闻扫描频率为每 30 分钟
- [x] 记录技术架构、来源政策和阶段路线图
- [ ] 项目所有者审阅并确认文档

验收：文档与项目约束一致，无未批准的付费依赖。

## 阶段 2：新闻源验证与内容模型

- 建立候选来源清单并逐个验证官方 Feed / API。
- 记录版权条款、访问限制和许可状态。
- 选定首批少量测试来源。
- 定稿 Markdown 文章字段、分类体系、去重规则和审核状态。
- 使用样例数据测试 RSS 解析，不启动持续调度。

验收：每个启用来源均有可追溯的官方入口和使用规则；样例解析通过。

## 阶段 3：静态网站最小版本

- 初始化 Astro + TypeScript 项目。
- 建设首页、分类页、新闻详情页、关于 / 来源说明页。
- 实现土耳其语页面元数据、SEO 基础和 Sitemap。
- 用本地样例 Markdown 内容构建。
- 检查移动端布局、页面速度、无障碍与链接。

验收：本地构建成功，样例页面内容正确；未接入生产采集。

## 阶段 4：采集与编辑流水线（先手动触发）

- 编写 RSS / API 获取与规范化逻辑。
- 实现去重、时间检查、来源记录和错误日志。
- 接入经批准的 AI 编辑服务前，先确认供应商与费用上限。
- 实现土耳其语标题、摘要、分类、标签及质量检查。
- 建立普通 / 重要 / 重大新闻的审核门槛。
- 先以手动触发方式测试，不启用 30 分钟生产计划任务。

验收：测试数据通过；重复、过期、无来源和内容冲突案例按规则处理；成本可测算。

## 阶段 5：自动调度与安全部署

- 将调度频率设置为每 30 分钟一次。
- 设置并发保护、重试上限、失败记录和运行指标。
- 配置 GitHub Secrets，不在仓库保存密钥。
- 验证 Astro 构建及 Cloudflare Pages Direct Upload。
- 验证部署失败回滚和额度监控。
- 先小范围观察，再由项目所有者批准正式启用。

验收：调度、构建、部署、日志和成本监控均经过测试。

## 阶段 6：上线前审核与发布

- 审查土耳其语内容质量与事实准确性。
- 完成土耳其当地法律与版权核查。
- 检查来源署名、隐私、纠错和联系信息。
- 绑定域名（如需购买域名，先单独确认预算）。
- 进行安全、SEO、移动端和可用性检查。
- 经项目所有者最终批准后公开发布。

## 阶段 7：运行观察与优化

- 观察采集成功率、延迟、重复率和编辑质量。
- 观察页面访问、搜索索引和错误率。
- 根据数据调整来源质量与分类，不改变每 30 分钟的固定扫描要求，除非项目所有者明确批准。
- 只有在确有必要并完成成本评估后，才考虑数据库、对象存储或付费服务。
